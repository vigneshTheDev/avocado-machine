# Project ground rules

## Algorithm practice

- Prioritize clear, simple implementations that expose the algorithm and its data structures.
- Assume exercise inputs satisfy the problem's stated constraints and operation preconditions. Document needed assumptions in the problem description.
- Keep solutions focused on the algorithm; omit defensive input validation, custom errors, and recovery behavior unless the exercise explicitly requires them.
- Test algorithm correctness with representative valid inputs and meaningful state transitions. Include valid boundary cases when they exercise the algorithm, such as duplicates or a single-element input when permitted by the problem.
- Keep invalid-input and error-handling tests out of exercise suites unless that behavior is an explicit learning objective.

These rules apply to exercise descriptions, templates, solutions, and tests. The CLI and practice infrastructure retain validation needed for their own behavior.
